# TinyDays 디자인 수정 브리프

## 목적

TinyDays MVP의 현재 화면을 부모가 매일 빠르게 쓰기 좋은 모바일 앱 경험으로 정리한다. 이번 디자인 수정의 중심은 새로운 기능 추가가 아니라, 이미 구현된 핵심 기록 루프를 더 명확하고 빠르게 만드는 것이다.

## 제품 한 줄 설명

TinyDays는 가족 안에서 아기 돌봄 기록을 빠르게 남기고, 오늘 요약과 타임라인, 생활 패턴, 사진 기록으로 다시 확인하는 모바일 앱이다.

## 핵심 사용자

- 주 사용자: 신생아 또는 영유아를 돌보는 부모.
- 사용 상황: 수유, 기저귀, 수면, 체온, 목욕 같은 이벤트가 발생한 직후 한 손으로 빠르게 기록한다.
- 사용 맥락: 피곤하고 시간이 부족한 상태에서 짧게 입력한다. 화면을 오래 읽거나 복잡한 선택을 하기 어렵다.

## 디자인 목표

- 홈에서 3초 안에 주요 기록을 시작할 수 있게 한다.
- 텍스트 기록과 빠른 기록의 우선순위를 명확히 한다.
- 파싱 결과 확인 화면은 "저장 전 확인"이라는 의미가 즉시 이해되어야 한다.
- 오늘 요약은 부모가 지금 필요한 상태를 먼저 보게 한다.
- 기록, 인사이트, 사진, 가족 탭은 기능은 단순하지만 빈 화면과 오류 상태까지 완성도 있게 보이게 한다.
- 아기 사진, 건강 기록, 가족 정보가 민감한 데이터라는 인상을 준다. 공개 공유나 소셜 서비스처럼 보이지 않게 한다.

## 현재 구현 화면

### 홈

현재 포함 요소:

- 앱 이름
- 선택된 아기 이름과 D+ 표시
- 마지막 기록 상태
- 오늘 수유, 수면, 기저귀, 마지막 기록 요약
- 텍스트 기록 입력
- 파싱 결과 확인 패널
- 빠른 기록 버튼
- 최근 타임라인

수정 요청:

- 홈의 정보 위계를 다시 잡는다. 첫 화면에서 아기 상태, 오늘 요약, 기록 시작 액션이 바로 보여야 한다.
- 빠른 기록 버튼은 손가락으로 누르기 쉬운 크기와 간격을 유지한다.
- 텍스트 기록은 보조 입력이지만 숨겨져서는 안 된다. 예시 문장을 통해 자연어 입력 가능성을 알려준다.
- 파싱 결과 확인은 임시 모달 또는 하단 시트처럼 "저장 전 단계"로 느껴지게 제안해도 된다.
- "파싱하기" 같은 기술적인 문구는 부모 관점의 표현으로 바꿀 수 있다.

### 기록 탭

현재 포함 요소:

- 날짜 선택
- 기록 타입 필터
- 날짜별 타임라인
- 기록 수 표시
- 빈 상태

수정 요청:

- 날짜 선택과 타입 필터가 좁은 모바일 화면에서 과하게 복잡해 보이지 않게 정리한다.
- 타임라인 아이템은 시간, 기록 타입, 수치, 메모가 빠르게 스캔되어야 한다.
- 수정/삭제 기능이 이후 붙을 수 있도록 아이템 구조에 여지를 둔다.

### 인사이트 탭

현재 포함 요소:

- 최근 7일 기간
- 다음 행동 안내
- 수유, 수면, 기저귀 7일 요약

수정 요청:

- 인사이트는 "예측"보다 "기록 기반 참고"로 보이게 한다.
- 수치 카드가 과장되거나 의료 조언처럼 보이지 않게 한다.
- 다음 행동 안내는 룰 기반 힌트임을 UI 톤으로 표현한다.

### 사진 탭

현재 포함 요소:

- 사진 추가 버튼
- 권한 오류와 저장 오류 메시지
- 날짜별 사진 그리드
- 빈 상태

수정 요청:

- 사진은 가족 비공개 기록이라는 느낌을 준다.
- 첫 사진 추가 전 빈 상태가 자연스럽고 따뜻해야 한다.
- 업로드 버튼은 명확하되 영상 생성, 댓글, 반응 같은 비목표 기능을 암시하지 않는다.

### 가족 탭

현재 포함 요소:

- 가족 이름
- 가족 정보 입력
- 아기 이름과 생년월일
- 등록된 아기 정보
- 현재 구성원과 권한

수정 요청:

- 가족 설정 화면은 운영 도구처럼 차분하게 정리한다.
- `family_id`, `child_id` 같은 개발용 정보는 최종 사용자 화면에서는 숨기거나 디버그/보조 정보로 낮춘다.
- 현재 MVP에서는 복잡한 초대와 권한 체계를 넣지 않으므로, 초대 기능처럼 보이는 UI는 만들지 않는다.

## 내비게이션

초기 탭은 아래 5개를 유지한다.

- 홈
- 기록
- 인사이트
- 사진
- 가족

탭 이름은 짧게 유지한다. 아이콘 제안은 가능하지만, 탭 수나 정보 구조를 크게 바꾸는 제안은 별도 논의가 필요하다.

## 톤앤매너

- 가족 앱이지만 지나치게 귀엽거나 장식적인 방향은 피한다.
- 부모가 반복해서 쓰는 도구이므로 조용하고 안정적인 느낌을 우선한다.
- 건강 기록이 포함되므로 신뢰감이 중요하다.
- 색상은 단일 파스텔 톤에만 의존하지 말고, 기록 타입과 상태를 구분할 수 있게 한다.
- 카드 남용보다 섹션, 리스트, 버튼의 위계를 명확히 한다.

## 카피 가이드

- 기술 용어보다 행동 중심 문구를 사용한다.
- 예: "파싱하기"보다 "기록 확인하기" 또는 "내용 확인"
- 예: "confidence"보다 "확인이 필요해요"
- 예: "저장소 오류"보다 "기록을 불러오지 못했습니다"
- 불안을 주는 표현은 피하고, 다음 행동이 분명한 문구를 사용한다.

## 반드시 지킬 제약

- 모바일 앱 우선이다. 웹 대시보드 디자인은 이번 범위가 아니다.
- 서버 AI, 공개 공유, 소셜 피드, 커머스, 커뮤니티는 이번 디자인에 포함하지 않는다.
- 낮은 신뢰도 또는 음성/텍스트 파싱 결과는 저장 전 확인 흐름을 거쳐야 한다.
- 사진, 건강 기록, 가족 정보는 비공개 데이터로 다룬다.
- 권한 모델은 `parent`, `family` 수준을 넘어서지 않는다.

## 디자이너 산출물 요청

- 모바일 기준 주요 화면 시안
  - 홈
  - 기록
  - 인사이트
  - 사진
  - 가족
- 홈의 핵심 기록 플로우
  - 빠른 기록
  - 텍스트 입력
  - 파싱 결과 확인
  - 저장 후 최근 타임라인 반영
- 빈 상태, 로딩 상태, 오류 상태
- 버튼, 입력 필드, 탭, 기록 아이템, 요약 카드의 기본 컴포넌트 가이드
- 기록 타입별 시각 구분 방식
  - 수유
  - 수면
  - 기저귀
  - 체온
  - 목욕
  - 메모
  - 비타민
  - 약

## 우선순위

1. 홈의 기록 시작 경험과 오늘 요약 위계.
2. 파싱 결과 확인 화면.
3. 기록 탭의 날짜별 타임라인 가독성.
4. 사진 탭의 빈 상태와 업로드 진입.
5. 가족 탭의 설정 화면 정리.

## 검토 기준

- 부모가 홈 첫 화면에서 무엇을 해야 할지 바로 알 수 있는가?
- 빠른 기록 버튼을 한 손으로 쉽게 누를 수 있는가?
- 텍스트/음성 기록이 저장 전에 확인된다는 흐름이 분명한가?
- 오늘 요약과 최근 타임라인이 같은 데이터 흐름처럼 보이는가?
- 비공개 가족 기록 앱의 신뢰감이 있는가?
- MVP 비목표 기능을 암시하지 않는가?
